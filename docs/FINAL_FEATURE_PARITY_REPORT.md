## Implemented and tested slices

- Dedicated Central Admin web MFA, approved-access records, explicit permissions, token provenance, login replay limits, session-bound step-up and revocation. Six live paginated read workspaces: users, plants, orders, support, audit and sessions. No migration grants privileged access.
- Nonprivileged OTP delivery dependency: production always uses configured providers; synthetic tests inject an in-memory transport. Email now uses Postmark's documented field names and accepted receipt, fails without configuration, and only activates an OTP after delivery acceptance. Delivery failure preserves the previous OTP. No OTP/provider response body is logged. Eight approved email fixtures exercise enrollment, MFA, one-use recovery and logout; two approved phone fixtures exercise generated WhatsApp OTP once. Staff challenges cannot become a Central Admin enrollment/login path after a role change.
- Order-wide quantity production uses parent/material locks, immutable request IDs, recipe/version snapshots, precise stock movements and atomic rollback. Dispatch consumes produced quantity, validates driver/mixer availability and requires a stored challan and gate pass. Delivery records GPS/POD/evidence, reconciles quantity, releases fleet and notifies the customer.
- Billing creates an immutable delivered-order invoice and records bounded exact payments with repeat-request protection, concurrent balance checks and audit changes. Owner invoice summaries and ledger date serialization are repaired.
- Payroll serializes each plant/month, separates accountant draft/payment from owner approval/closure, creates exactly one salary expense, requires all active employees paid, and exports immutable versioned payslip snapshots. Full salary calculations from attendance and controlled reopen policy remain PARTIAL.
- Customer order repair accepts the actual mobile DTO, saved or inline sites, draft intent, KYC/name/mobile checks, approved plant eligibility, effective rate cards or accepted quotation totals and per-customer idempotency. Client estimates cannot set charges. Assistant intents are hashed, stored, bound to a customer, expiring and confirmed explicitly; changed prices require a new review. Order, concurrency, cancellation, dispatcher and automation guards passed PostgreSQL 16/18 run 38781019266.
- Automation rejects missing/placeholder credentials and stale leases. Unconfigured provider delivery returns an error and leaves the event uncompleted. Generic dispatcher status changes cannot bypass dedicated workflows. Customer cancellation is scoped, locked and transactional. These guards passed PostgreSQL 16/18 run 38781019266.
